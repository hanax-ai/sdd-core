# Adopter Constitution Template

## Authority and ownership

This repository owns its product, implementation, evidence, and local
decisions. SDD-Core supplies adopted governance; it does not own
the adopter or grant authority by installation, validation, readiness, review,
integration state, or workflow state.

Only an explicitly recognized human authority can issue Gate 1, Gate 2, merge,
release, publication, or other consequential authority. A local directive must
name the exact governed artifact or bounded outcome.

## Protected provisions

The adopter MUST preserve the ten protected provisions listed in
[the adoption record](../../.sdd-core/adoption.yaml): human authority, Gate 1,
Gate 2, WIP non-authority, source grounding, no silent bypass, scope isolation,
cross-repository boundaries, adopter ownership, and tooling governance. They
cannot be excluded, silently renamed, or tailored into weaker obligations.

## Lifecycle

Ideas and analysis remain non-authoritative WIP. Gate 1 authorizes only the
named artifact's promotion into formal planning. Gate 2 authorizes only the
named reviewed implementation plan. Evidence demonstrates what occurred; it
never grants approval.

## Repository boundaries

Cross-repository changes require separate, explicit authorization naming both
source and target. External integrations may report readiness or evidence, but
they cannot mint authority or broaden a mission.

## Local routing

- Collaborative thought belongs under [WIP](../../wip/README.md).
- Durable conversation records follow the
  [conversation policy](../../conversations/SYNC-POLICY.md).
- Grounded sources are registered in
  [knowledge instructions](../../knowledge/instructions.md).
- Assistant adapters remain subordinate to this constitution.
